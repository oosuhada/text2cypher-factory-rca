# 제품 리팩터링 6단계 — 검색형 그래프 탐색

## 목적

기존 Graph Explorer는 노드의 정확한 식별값을 알고 있어야 했다. 이 단계는
사용자가 ID를 모르는 상황에서도 노드 속성 일부를 검색하고, 선택한 노드에서
최대 3-hop 관계를 읽기 전용으로 펼칠 수 있게 한다.

## 구현

- `GraphCatalogService.search_nodes`
  - 허용 목록에 포함된 노드 라벨만 조회
  - 라벨별 검색 가능 속성을 서버에서 고정
  - 부분 문자열 검색, 최대 50개 결과
  - Cypher 문자열에 사용자 입력을 직접 삽입하지 않고 파라미터로 전달
- `GET /api/v1/graph/search`
  - `label`, `q`, `limit` 계약과 공백·범위 검증
- Streamlit Graph Explorer
  - 노드 유형과 검색어 입력
  - 검색 결과의 사람이 읽을 수 있는 이름 표시
  - 선택한 결과를 즉시 1~3-hop 관계 그래프로 전환
  - 정확한 ID 직접 입력 방식도 보조 경로로 유지
- Next.js Graph Explorer
  - 검색 결과 카드와 선택 즉시 관계 탐색
  - 기존 Cytoscape 기반 인터랙티브 근거 그래프 재사용

## 안전 경계

- 쓰기 쿼리는 사용하지 않는다.
- 라벨과 검색 속성은 서버의 허용 목록에서만 선택한다.
- 사용자 검색어와 limit은 Neo4j 파라미터로 전달한다.
- 그래프 탐색 깊이는 최대 3-hop, 경로 결과는 최대 100개로 제한한다.

## 완료 기준

- 부분 문자열로 실제 노드를 찾을 수 있다.
- 검색 결과에서 정확한 식별값을 선택해 부분 그래프를 조회할 수 있다.
- 지원하지 않는 라벨, 공백 검색어, 범위 밖 limit은 거절한다.
- Streamlit과 Next.js가 동일한 FastAPI/서비스 계약을 사용한다.
