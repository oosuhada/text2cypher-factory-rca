# CiP-DMD 데이터 갭 및 대응

## 결론

CiP-DMD 선택으로 P3 MVP를 막던 핵심 데이터 문제는 해소됐다. 완제품·구성품·공정·anomaly·품질검사가 `part_id`로 연결되므로 Text-to-Cypher 기반 genealogy·RCA 후보 조회가 가능하다.

단, 최초 LOT·설비부품 중심 가정과는 데이터 의미가 다르므로 범위를 다음처럼 확정했다.

- LOT 대신 개별 완제품·구성품 `part_id` 사용
- 설비 소모품 대신 제품 구성품 관계 추적
- 불량 코드 대신 원본 `qc_pass`와 공정 anomaly 사용
- 센서 HDF5는 1차 MVP에서 제외

## 남은 갭과 처리

| 갭 | 영향 | 처리 |
|---|---|---|
| 완전 genealogy가 767/802 | 35개 완제품의 전체 경로 불완전 | 격리 로그, 전체 경로 Gold 모집단에서 제외 |
| placeholder record 1건 | 잘못된 component 노드 생성 가능 | ETL에서 명시적으로 제외 |
| 설비별 고유 ID 부족 | 동일 종류 설비 간 비교 제한 | 공정별 machine type 노드만 사용 |
| 설비 소모품·교체 이력 없음 | 부품 교체 기반 RCA 불가 | 제품 구성품·공정 anomaly RCA로 한정 |
| 생산 로그에 `part_id` 없음 | 이벤트를 개별 부품과 직접 연결 불가 | 날짜 기반 참고 정보로만 보존 |
| CSV와 JSON 측정 수 차이 | 두 원본 간 행 불일치 | JSON 기준, CSV 교차검증 |
| anomaly class 의미 제한 | 고장 유형을 임의 해석할 위험 | 원본 class 값만 표시 |
| HDF5 미다운로드 | 센서 시계열 분석 불가 | P3 핵심 범위 밖, 확장 단계로 연기 |

## 범위 밖이라고 명시할 분석

- 특정 설비 부품 교체가 불량의 원인이라는 주장
- anomaly class에 임의의 물리적 고장명 부여
- 그래프 연결만으로 인과관계 확정
- 개별 `part_id`와 생산 로그 이벤트의 근거 없는 JOIN
- 센서 시계열 기반 이상감지 성능 주장

## 단계 판정

위 갭은 데이터 정합성 처리와 범위 제한으로 관리 가능하며 P3 핵심 구현을 막지 않는다. 2단계 데이터 게이트는 **PASS**이고, 3단계 최소 그래프 스키마 설계로 진행한다.
